## 📂 카테고리 관리 (평가 #23)

프로그램에서 사용하는 카테고리는 코드 상단의 **상수(CATEGORIES)** 로 관리합니다.

\```python

CATEGORIES = ["업무", "게임", "일상"]
\```

- **변경 지점**: `app.py` 최상단의 `CATEGORIES` 리스트를 수정하면 전체에 반영됩니다.
- 카테고리 추가/삭제 시 이 목록만 수정하면 되도록 상수화했습니다.

## 🗂️ 데이터 구조 설계 (평가 #13, #16)

프롬프트 데이터는 **리스트 안에 딕셔너리** 형태로 저장합니다.

\```python
prompts = [
    {"제목": "회의록 정리", "내용": "...", "카테고리": "업무", "즐겨찾기": False},
    ...
]
\```

### 자료구조 선택 이유 (장단점 비교)

| 자료구조 | 장점 | 단점 |
|----------|------|------|
| **리스트(List)** | 순서 유지, 번호로 접근 쉬움, 추가/조회 간단 | 특정 항목 검색 시 전체 순회 필요 |
| **딕셔너리(Dict)** | 필드 이름(제목/내용 등)으로 명확하게 접근 가능 | 키를 정확히 알아야 접근 가능 |

→ **선택 이유**: 프롬프트는 "순서가 있는 여러 개의 항목"이므로 **리스트**로 관리하고,
각 프롬프트는 "제목·내용·카테고리 등 여러 필드"를 가지므로 **딕셔너리**로 표현했습니다.
이 조합으로 번호 접근과 필드 접근을 모두 편리하게 처리할 수 있습니다.

## 🔁 반복문(while) 및 종료 조건 설계 (평가 #17)

메뉴는 `while True` 무한 반복으로 구현했습니다.

\```python
while True:
    show_menu()
    choice = input("번호를 선택하세요: ")
    if choice == "0":
        break  # 0 입력 시 반복 종료
\```

- **설계 의도**: 사용자가 여러 기능을 **연속으로** 사용할 수 있도록 무한 반복을 사용했습니다.
- **종료 조건**: `0`을 입력하면 `break`로 반복을 빠져나가 프로그램이 종료됩니다.

## ✅ 입력값 검증 규칙 (평가 #14)

프로그램은 다음과 같은 입력 검증을 수행합니다.

| 상황 | 검증 방법 | 처리 |
|------|-----------|------|
| 숫자가 아닌 입력 | `.isdigit()` 검사 | 안내 문구 출력 |
| 범위를 벗어난 번호 | `1 <= 번호 <= len(prompts)` 검사 | 안내 문구 출력 |
| 목록이 비어있음 | `if prompts == []` 검사 | "등록된 프롬프트 없음" 안내 |
| 카테고리 유효성 | `CATEGORIES` 목록에 포함되는지 검사 | 잘못된 카테고리 안내 |

  - `feat: 즐겨찾기 기능 구현`

### 브랜치 정책

  - `feature/favorite` : 즐겨찾기 기능 개발 브랜치

- **병합 시점**: 해당 기능이 완성되어 정상 작동을 확인한 후 main에 병합했습니다.

## 🧩 함수 분리 및 역할 설명 (평가 #12)

프로그램은 기능별로 함수를 분리하여 구현했습니다.
각 함수는 하나의 책임(기능)만 담당하도록 설계했습니다.

| 함수 이름 | 역할 |
|-----------|------|
| `show_menu()` | 메뉴 목록을 화면에 출력 |
| `add_prompt()` | 새 프롬프트를 입력받아 추가 (중복 제목 검사 포함) |
| `show_list()` | 전체 프롬프트 목록 출력 |
| `show_category()` | 특정 카테고리 항목만 출력 |
| `search_prompt()` | 제목·내용에서 키워드 검색 |
| `show_detail()` | 선택한 프롬프트 상세 정보 출력 |
| `toggle_favorite()` | 즐겨찾기 추가/해제 (토글) |
| `show_favorites()` | 즐겨찾기한 항목만 출력 |

- **함수 분리 이유**: 기능마다 함수를 나누면 코드를 읽기 쉽고, 수정·재사용이 편리하며,
  한 기능에 문제가 생겨도 다른 기능에 영향을 주지 않습니다.

## 🔎 검색 기능 설명 (평가 #8)

검색은 **제목과 내용 모두**를 대상으로 합니다.

\```python
제목 = prompts[i]["제목"]
내용 = prompts[i]["내용"]
if 검색어 in 제목 or 검색어 in 내용:
    # 검색 결과에 포함
\```

- `or`를 사용하여 제목 **또는** 내용에 검색어가 포함되면 결과에 표시합니다.

## 🔁 중복 제목 처리 정책 (평가 #21)

프롬프트 추가 시 **같은 제목이 이미 존재하는지 검사**합니다.

- **정책**: 중복 제목은 **차단(거부)** 합니다.
- 같은 제목이 있으면 추가하지 않고 안내 메시지를 출력합니다.

\```python
# 제목 중복 검사
중복 = False
for p in prompts:
    if p["제목"] == 제목:
        중복 = True
        break

if 중복:
    print(f"⚠️ 이미 '{제목}' 제목이 있어요!")
else:
    prompts.append(새프롬프트)
\```

- **선택 이유**: 같은 제목이 여러 개면 검색·조회 시 혼란스러우므로,
  제목을 고유하게 유지하기 위해 중복을 차단하는 방식을 선택했습니다.
